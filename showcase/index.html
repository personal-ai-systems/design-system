Colour roles

Every public colour is a role. Components reference the role, so a palette change is an edit to themes/provisional-light.tokens.json (and its dark pair) plus a rebuild — never a component change.

Cards

Semantic, not decorative

Colour roles

A role name describes a job. Rebranding replaces theme values; it does not rename classes or edit components.

Buildless consumption

Plain HTML and CSS

The generated stylesheets are the deliverable. A consumer imports the variables file, and imports base and components only if it wants the default look.

Checked, not asserted

scripts/validate.mjs, tests/

Role completeness, reference validity, deterministic output, contrast minimums and colour discipline are all machine-checked.
